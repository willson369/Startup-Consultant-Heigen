# 黑根技术选型

## 结论

黑根完全复用 `pbathuri/entrepreneur-persona-llm` 的技术架构：它是一个模型无关的提示词包，而不是 Next.js、Vercel AI SDK 或特定云服务项目。因此本项目不采用、也不推荐额外的前端框架、后端语言、AI SDK、数据库或模型供应商。

## 技术栈清单

| 层级 | 采用内容 | 基于原项目的理由 |
| --- | --- | --- |
| 核心逻辑 | Markdown 格式的 `SKILL.md` | 原项目把指导人格、工作流与质量标准定义为可注入任意 LLM 的系统提示词 |
| 知识组织 | `references/` Markdown 文件 | 原项目用按需加载的参考资料承载评审标准、验证框架与问题库 |
| 输出骨架 | `assets/` Markdown 模板 | 原项目通过可复制模板约束商业计划书与路演输出结构 |
| 模型接口 | 任意支持系统/开发者/自定义指令的 LLM 产品 | 原项目明确模型无关，可用于 ChatGPT、Gemini、Copilot、Cursor、Claude 等 |
| 会话历史 | 宿主 LLM 产品的原生历史能力 | 原项目不实现独立存储服务，按宿主产品能力保存会话 |
| 文档导出 | 宿主产品将 Markdown 输出下载/保存 | 原项目的输出资产均为 Markdown，可直接复用 |

## 复用方式

1. 将 `skills/heigen-advisor/SKILL.md` 放入宿主产品的系统、开发者或自定义指令上下文。
2. 同时提供同目录下 `references/` 与 `assets/` 作为可读取文件。
3. 使用宿主产品已有的会话记录保存历史，使用其 Markdown 导出能力保存 BP 或路演脚本。

该方案不引入参考项目中不存在的 Web 框架、SDK、API 或数据组件，满足轻量与提示词工程优先的要求。
